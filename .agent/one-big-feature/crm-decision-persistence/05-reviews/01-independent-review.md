## One non-blocking design note for follow-up (not a blocker for this PR)

`add-interaction.py`'s update-in-place match key is `(source_ref, contact_id)` only, and a caller that matches that key **without** passing `--decision` will overwrite existing decisions with `[]` (arg default is `None → []`, not "leave unchanged"). Current callers are safe because `calendar:`/`gmail:`/`fireflies:` source_ref prefixes never collide with each other, and `ingest-meeting-decisions.py` skips calling the writer at all when a meeting has neither decisions nor deal_state — so this can't currently fire. But it's an implicit invariant ("no future caller reuses a `fireflies:` source_ref without also carrying forward decisions") that isn't enforced or documented anywhere in code. Worth a one-line comment or a `--decision` semantics guard if another connector is ever added.
